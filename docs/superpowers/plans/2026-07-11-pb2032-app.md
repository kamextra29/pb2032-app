# pb2032-app — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PWA hors-ligne (Android terrain / Windows bureau) d'identification de branchements GRDF PB 2032 : import du fichier Excel client, fiches consultables/éditables avec listes déroulantes et calculs automatiques, photos compressées renommées, export Excel « chirurgical » strictement conforme, réimport avec fusion.

**Architecture:** JavaScript vanilla en modules ES (aucun framework), IndexedDB pour les données, Web Worker pour les traitements lourds (XML de 60 Mo), JSZip vendoré comme seule dépendance d'exécution. La logique métier (`js/core/*`) est pure et testée avec `node --test` ; l'interface (`js/ui/*`) est vérifiée dans le navigateur. L'export ne regénère jamais le fichier : il réinjecte les valeurs saisies dans le XML d'origine, bloc `<row>` par bloc `<row>`.

**Tech Stack:** HTML/CSS/JS (ES modules), JSZip 3.10.1 (vendoré), IndexedDB, Web Worker, `BarcodeDetector`, Service Worker (PWA), `node --test` + `fake-indexeddb` (dev), GitHub Pages.

**Référence :** spec validée `docs/superpowers/specs/2026-07-10-pb2032-app-design.md` (notée « §N » ci-dessous). Le fichier client réel (`C:\Users\olivi\Downloads\Annexe 7 LOT 5 SLTP BFC CR - Marché PB2032.xlsx`) ne doit **jamais** entrer dans le dépôt (`.gitignore` exclut `*.xlsx`) ; les tests utilisent une fixture synthétique générée par script.

- [ ] **Step 2 : run → FAIL** — `node --test test/regles.test.mjs`

- [ ] **Step 3 : implémentation minimale**

```js
export function calculerPression(accessoires, bague, ref) {
  const [dtc, dt, rc, seul, impro] = ref.equipements;
  const [MPB, BP, A_RENSEIGNER] = ref.pressions;
  const baguesProtectrices = ref.bagues.slice(1); // PBDI, MBDI, DPBE, DPBA
  if (accessoires === dtc || accessoires === dt) return MPB;
  if (accessoires === rc) return BP;
  if (accessoires === seul || accessoires === impro)
    return baguesProtectrices.includes(bague) ? MPB : A_RENSEIGNER;
  return A_RENSEIGNER;
}
```

### Task 9 : `xlsx-writer.js` — injection chirurgicale

**Files:** Create: `js/core/xlsx-writer.js` ; Test: `test/xlsx-writer.test.mjs`

API : `export async function exporterFichier(octetsOriginaux, branchements, dossier)` → `Uint8Array`.
`branchements` = enregistrements du store (avec `saisies`, `ligne`, `ajoute`).

Algorithme (§9) :
1. Charger le zip, lire le XML de la feuille PB (chemin fourni par `dossier.cheminFeuillePb`).
2. Construire la liste des modifications : pour chaque branchement avec `saisies` non vides →
   liste de `{ref: 'O7', valeur, type}`. Colonnes autorisées **exclusivement** : A–K (corrections),
   O,P,Q,R,S,T,U, AE,AF,AG, AH–AN. Types : U/AG/AM → nombre ; A–K → nombre si `/^[1-9]\d*$/`
   sinon texte ; le reste → texte. Exception V (§3.4) : si `vEnDur` et S ou T modifiée →
   écrire `calculerPression(...)` en texte dans V.
3. Branchements ajoutés : leur attribuer les premières lignes vides après
   `dossier.derniereLigneDonnees` (935+ dans le vrai fichier, 12+ dans la fixture), dans
   l'ordre de création, sans dépasser la fin du tableau.
4. Reconstruire le XML **en segments** (jamais de concaténation répétée sur 60 Mo) : parcourir
   les blocs `<row>` séquentiellement ; pour une ligne modifiée, réécrire les `<c>` visés :
   - cellule existante : conserver l'attribut `s=`, remplacer contenu et `t=` ;
   - cellule absente du bloc : l'insérer à la bonne position (ordre des colonnes) sans `s=` ;
   - texte → `t="inlineStr"` + `<is><t xml:space="preserve">…</t></is>` (jamais toucher
     `sharedStrings.xml`) ; nombre → `<v>…</v>` ; échapper `& < > " '`.
   - ne **jamais** modifier une cellule hors liste blanche (L–N, W–AD, AO, V sauf exception) ni
     un `<f>` existant.
5. `workbook.xml` : ajouter `fullCalcOnLoad="1"` sur `<calcPr>` (le créer s'il manque).
6. Vérification interne post-injection (§11) : XML bien formé (comptage équilibré `<row`/`</row>`,
   pas de `<c` orphelin) + nombre de cellules réécrites == attendu ; sinon lever une erreur
   explicite (l'UI l'affichera) et ne rien retourner.
7. Regénérer le zip (DEFLATE). Les entrées non touchées sont recopiées telles quelles.
